    1.2 Architecture & Design Principles

    This document details the architectural patterns, structural organization, and design standards governing the Secretary [App](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/client/src/App.jsx) codebase. The project follows a monorepo structure and emphasizes strict separation of concerns through MVC principles, Atomic Design, and a Controller-Service-Repository pattern.

    1. Monorepo Structure & MVC Pattern

    The codebase is organized as a monorepo that separates the Client (Frontend) and Server (Backend), both adhering to the Model-View-Controller (MVC) pattern.

    Architectural Responsibilities

    Layer Location Responsibility
    View client/src/components/ Atomic components (Atoms, Molecules, Organisms).
    Controller (FE) client/src/features/*/hooks/ Domain logic, state management, and orchestration.
    Model (FE) [client/src/hooks/useFetch.js](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/client/src/hooks/useFetch.js) Data fetching and global context state.
    Controller (BE) server/controllers/ HTTP request parsing, validation, and response formatting.
    Service (BE) server/services/ Pure business logic, complex calculations.
    Repository (BE) server/repositories/ SQL query execution and data sanitization.

    2. Frontend: Atomic Design & Feature Modules

    The frontend utilizes Atomic Design for component architecture and a Feature-based folder structure.

    Atomic Design Hierarchy

    • Atoms: Smallest units (e.g., <Button/>, <Icon/>). Direct use of native elements is prohibited.
    • Molecules: Simple combinations (e.g., FormField, [`SearchBar`](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/client/src/components/molecules/SearchBar.jsx)).
    • Organisms: Complex sections (e.g., [`GlobalWhatsappMessenger`](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/client/src/components/organisms/GlobalWhatsappMessenger.jsx), [`DaySchedule`](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/client/src/features/appointments/components/schedule/DaySchedule.jsx)).
    • Templates/Pages: High-level layouts and orchestrators.

    Feature-Based Organization

    Logic is encapsulated within client/src/features/. Each feature follows: * Orchestrator: FeaturePage.jsx coordinates components and hooks. * Controller: useFeatureController.js manages state and side effects. * Execution: Components like [DaySchedule](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/client/src/features/appointments/components/schedule/DaySchedule.jsx).jsx receive data and handlers from the controller. * Barrel File: [index](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/server/controllers/appointments/index.js).js exports only necessary entities.

    3. Backend: Controller-Service-Repository

    • Repositories: Execute raw SQL using placeholders (?) to prevent injection.
    • Services: Centralize complex logic (e.g., [statsService](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/server/services/finance/statsService.js).js aggregates data from multiple repositories).
    • Controllers: Map HTTP status codes and handle error reporting via i18n keys.

    4. CSS Conventions & Design Tokens

    Uses Vanilla CSS with BEM (Block Element Modifier) naming. CSS-in-JS and TailwindCSS are strictly prohibited. * Block: .appointment-report * Element: .appointment-report__table * Modifier: .appointment-report__row--weekend

    Design Principles for Styles

    • One Component = One CSS: Every .jsx file must have a corresponding .css file.
    • Isolation: Components cannot override styles of children via nesting.
    • No !important: Use of the !important flag is prohibited.

    5. Key Design Principles

    • DRY: Common logic is extracted into reusable hooks like useFetch.
    • Performance: Major feature routes are loaded lazily using React.lazy() and Suspense.
    • Error Handling: Form validation is kept in the Feature Controller; [errors](https://github.com/jmrodev/secretary-app/blob/fix/react-19-modernization-final/server/utils/core/errors.js) are cleared on user interaction (onChange).
